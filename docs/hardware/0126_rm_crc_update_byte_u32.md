# ESP32-S3 device result: `cv_crc_update_byte_u32`

## Purpose and category

Accepted streaming primitive that advances a caller-owned raw reflected CRC-32 state by one byte using a caller-supplied reflected polynomial. It performs no initialization or final XOR and stores no hidden state. Category: incremental packet/serial/storage processing.

## Board and build

- ESP32-S3 Xtensa LX7 at 240 MHz; COM36.
- Arduino-ESP32 core 3.3.10; Xtensa GCC 14.2.0.
- Accepted production implementation compiled into the device harness.
- Sketch footprint: 310,448 bytes flash and 23,344 bytes static RAM including runtime, 256-entry CRC-32 table, stream buffer, and tests; not primitive-only.

- Exhaustive all 256 bytes across 256 deterministic raw CRC states: 65,536 combinations.
- 250,000 deterministic full-width raw state, byte, and arbitrary polynomial triples (seed `0x524D0126`) compared against an independent four-bit lookup oracle.

## Use and limitations

Useful when a bounded-memory receiver processes UART, radio, storage, or framed protocol bytes as they arrive and needs a configurable reflected polynomial. The caller must maintain raw-state initialization/finalization conventions. For high byte rates, inline/table/block implementations or hardware CRC may be faster. This handles reflected right-shifting polynomials only and is not authentication.
