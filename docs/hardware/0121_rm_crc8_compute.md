# ESP32-S3 device result: `cv_crc8_compute`

## Purpose and category

This accepted production primitive computes CRC-8/SMBus PEC: width 8, polynomial `0x07`, init/xorout zero, no reflection. Category: I2C/SMBus communications and packet error detection.

## Board and build

- ESP32-S3 Xtensa LX7 at 240 MHz; COM36.
- Arduino-ESP32 core 3.3.10; Xtensa GCC 14.2.0.
- Accepted production implementation compiled in a standalone test sketch.
- Sketch footprint: 310,408 bytes flash and 22,704 bytes static RAM, including runtime, generated 256-byte lookup oracle, 257-byte test buffer, and harness; not primitive-only.

## Device checks

- Empty input returns zero; null-data/zero-length accepted; null data/nonzero length rejected without changing output; null output rejected.
- Standard check string `123456789` returns `0xF4`.
- Exhaustive all 256 single-byte messages against a separate table-lookup oracle.
- 200,000 deterministic random messages with lengths 0..257, seed `0x524D0121`, compared against the table-lookup oracle. This oracle uses a generated byte lookup table while the candidate processes individual bits.
- Result: PASS; checksum `2998740661`.
- Timing on a fixed 32-byte message: 25 batches of 10,000 calls, mean 2,549.01 cycles per call, range 2,548.99–2,549.10 cycles/call.
- Stress cycle count covers variable-length payload generation and differential checks; batch timing measures repeated CRC calls.

## Use and limitations

Useful for generating/verifying SMBus PEC over bounded I2C transactions and small packets that require this exact profile. A hardware CRC unit or table-driven implementation may be faster for high throughput. CRC detects accidental corruption; it does not authenticate data. Other CRC-8 parameter sets require a different contract.
